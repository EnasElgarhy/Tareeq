User Consent Framework
For Developer: Ahmed Wahba

Overview
Users must explicitly consent to different uses of their data. This document specifies: - What consent options to present - When to ask for consent - How to implement consent UI - How to store consent choices
Legal principle: Opt-in, not opt-out. Users must actively choose to participate in research.

The Three Levels of Consent
Level 1: General Platform Use (Mandatory)
What it covers: Using Tareeq, taking the assessment, viewing results
User must agree to: Terms of Service + Privacy Policy
When to ask: Account creation or starting assessment (for anonymous users)
Level 2: Research Participation (Optional)
What it covers: Using their anonymized data for research studies, academic papers, platform improvement
User can choose: Yes or No
When to ask: End of assessment, before showing results
Level 3: Longitudinal Follow-Up (Optional)
What it covers: Contacting them in 6/12/24 months to ask about their actual career choices
User can choose: Yes or No
When to ask: End of assessment, before showing results
Level 4: University Data Sharing (Optional)
What it covers: Sharing their anonymized data with university research partners
User can choose: Yes or No
When to ask: End of assessment, before showing results

Step 3: Storing Consent
Database fields:
// In assessment_data table:
{
  // Consent flags
  consent_general_research: false, // Did they check the research box?
  consent_longitudinal_followup: false, // Did they check the follow-up box?
  consent_university_sharing: false, // Did they check the university box?

  // Audit trail
  consent_recorded_at: "2026-06-15T14:35:00Z",
  consent_language: "en", // 'en' or 'ar' (which language was consent presented in)
  consent_version: "v1.0", // Track if consent text changes

  // Withdrawal
  consent_withdrawn: false,
  consent_withdrawn_at: null
}
Code implementation:
// When user completes assessment and checks boxes:
const consentData = {
  consent_general_research: req.body.researchConsent || false,
  consent_longitudinal_followup: req.body.followupConsent || false,
  consent_university_sharing: req.body.universityConsent || false,
  consent_recorded_at: new Date(),
  consent_language: req.body.language, // 'en' or 'ar'
  consent_version: "v1.0"
};

// Save with assessment data
await db.assessment_data.create({
  ...assessmentResults,
  ...consentData
});

Code implementation:
// When user withdraws consent:
async function withdrawConsent(assessmentId) {
  await db.assessment_data.update(
    {
      consent_general_research: false,
      consent_longitudinal_followup: false,
      consent_university_sharing: false,
      consent_withdrawn: true,
      consent_withdrawn_at: new Date()
    },
    {
      where: { assessment_id: assessmentId }
    }
  );

  // Stop sending follow-up emails
  await cancelScheduledEmails(assessmentId);
}
Important: Once data is in an anonymized research dataset (e.g., exported CSV for a published paper), it cannot be removed (because we can’t identify which row was theirs). This must be explained clearly.

Special Case: Minors (Under 18)
Legal requirement varies by country:
UAE: Parental consent required for users under 21 (legal age of majority)
Saudi Arabia: Parental consent required for users under 18
Egypt: Parental consent required for users under 18

Edge Cases & FAQ
Q: What if user takes assessment without creating an account (anonymous)?
A: They can still consent to research. Store consent with their assessment_data using user_id_hash. If they later create an account, link the assessment to their account via email matching.
Q: What if user retakes assessment multiple times?
A: Ask for consent each time. Each assessment gets its own consent flags. User might consent for first assessment but not second.
Q: What if consent laws change?
A: Update consent_version to “v2.0” and re-prompt existing users with new consent text. Track which version they agreed to.
Q: What if user creates account in UAE but takes assessment in Saudi Arabia?
A: Use country_code from assessment location, not account registration. Consent laws follow where they are when they take the assessment.
Q: What if universities require more specific consent?
A: Add university-specific consent text in Phase 2. For MVP, general consent is sufficient.
